04 — About

The person behind the commits

I'm an electrical engineer who ended up in software — and I mean that literally: university taught me control systems, freelancing taught me deadlines, and repairing drones taught me that hardware always finds a new way to surprise you.

Somewhere along the way I started automating things. First receipts, then reports, then entire workflows. Today I build AI-powered tools, data pipelines, and web applications — mostly in Python and TypeScript, usually with AI coding assistants at my side and unit tests as my safety net.

I care that things work in the real world: documented, tested, deployed — and stoppable. If a system can't be turned off cleanly, it isn't finished.

How I work

  1. Understand first, code second. I write the problem down before I write the solution. Most bugs I've ever shipped were requirements I didn't question.
  2. Build with AI, verify like a skeptic. AI assistants make me faster; tests, browser QA, and reading the diff make me correct.
  3. Test like the user, not the author. Every project gets clicked through in a real browser — the way a stranger would break it.
  4. Document for the next person. A good README says what it is, how it works, how to stop it, and why it matters.
